# 竖屏动态背景

设置提供「黑色」和「动态模糊」，默认黑色。动态背景只装饰正在播放的竖屏画面两侧，中央画面保持原样；横屏不启用。不会改变播放源、解码器、音量、预取策略或播放器生命周期。

## 平台与边界

- 桌面 HTML5：从当前已播放的视频元素读取小尺寸画面。遇到跨域 Canvas 限制时回到黑边，不更改媒体的跨域配置或重新请求视频。
- Android 8 / API 26 及以上：HTML5 使用同一控制器；Media3 和 MPV 使用已有 Surface 的 PixelCopy 裁剪缩图。入口通过原生能力查询控制。原生 JPEG 编码在低优先级工作线程执行，不在 UI 线程编码。
- 旧 Android：隐藏设置，保持现有黑边。裁剪 PixelCopy API 需要 API 26；参见 [Android PixelCopy 文档](https://developer.android.com/reference/android/view/PixelCopy)。
- webOS：隐藏设置，不创建控制器，保持现有播放行为。

动态背景与剧集海报、下一集首帧过渡、尾帧遮罩是独立图层。切集开始即清空，只有新源已出画面后才重新采集，绝不拿本剧海报补位。原生播放器和 Surface 尺寸保持既有逻辑，不为装饰缩放或重建。

## 资源与降级

- 正常每 1 秒采集一次；原生最多一个 PixelCopy/编码任务，前端最多一个请求或图片解码。原生回调携带加载 ID 和请求序号，前端再验证播放身份及代际。
- 原生图片高度 192 像素；前端像素处理最长边 128；显示画布上限 1280×720，不随屏幕 DPR 放大。仅在小图上模糊、压暗并将中央视频区域擦为透明，边缘作柔和交接。
- 暂停和缓冲时停止采集；切集、拖动、前后台、退出播放及失败时取消前端任务并清空。原生任务不能强制中断，因此等待其回调或编码结束后再释放 Bitmap，过期结果丢弃。
- 单次绘制超过 24ms 时降至每 2 秒；连续 3 次超出此预算或一次超过 80ms 时禁用当前播放源的装饰。连续 3 次取帧/解码失败或超时同样回到黑边；单次原生请求等待上限 1.5 秒。
- 这些数值是装饰预算，不是播放超时。禁用状态在当前播放源内保留，暂停、布局或拖动不会不断重试；新源或用户重新启用设置可重试。任何装饰错误都不触发播放错误或切换播放器。

## 验证

Node 用例覆盖默认无工作、竖横屏、单请求、旧源回调、延迟图片解码、暂停/恢复、跨域失败、性能降级、布局、销毁以及设置焦点。Java 单元测试覆盖裁剪边界和请求校验，交由 CI 同时验证标准版和 MPV 版的编译、单元测试及 lint。

浏览器使用生产控制器和 CSS，配合本地生成的竖屏视频流验证动态侧边、中央透明、暂停停止和清理。该验证不代表 Android 真机 PixelCopy 和所有设备的性能已经验证；发布前仍需在 API 26+ 原生播放设备核对切集、暂停、后台恢复和影院模式。
