# 播放诊断

播放器控制栏“诊断”在音量之后、全屏之前；Android 隐藏音量时保持诊断可用。弹窗复用播放器已有焦点隔离和返回逻辑，默认焦点在“刷新诊断”，左右可移动到“关闭”，返回恢复原诊断按钮。打开不暂停、静音或解析视频。

数据在打开或刷新时固定为快照。视频、加载层、播放保护和设备字段立即采集；核心补充读取使用独立 2.5 秒 XHR，保留同一视频快照，返回只填对应源的核心和媒体状态。关闭、刷新或换播放器弹层取消并隔离迟到结果，不定时轮询。

- Android 设备厂商/型号/系统/API、应用版本、运行进程位数来自 Build 和 Process，不读取唯一序列号；核心架构来自实际运行的 Go runtime。系统支持的 ABI 列表不用于推断进程位数。
- Android 8+ 获取当前使用的 WebView 提供程序包版本；Android 6/7 不猜测安装的哪个包正在使用，显示当前 UA 的 Chromium 内核版本并标明来源。
- 播放时钟和缓冲来自当前 video；宽高为元数据，帧计数为浏览器报告的帧数，不代表硬件画面已经显示，也不声称获得实际解码器名字。
- MPV 版额外记录实际 `hwdec-current`、解码/渲染掉帧、音画差值和 `demuxer-cache-duration`；缓存时长只用于观察，不等同于可播放时长，也不会自动调整缓存预算。
- Media3 回退时额外记录选中的视频轨道格式（编码、Profile/Level 字符串、尺寸、帧率和颜色信息）、轨道支持等级、是否选中、未选中的 HEVC 轨道、实际视频解码器、首帧和渲染层。`FORMAT_HANDLED` 只表示 Media3 认为轨道可处理，仍须结合实际解码器、`onRenderedFirstFrame` 和 Surface/Texture 渲染结果判断画面是否可见。
- 状态展示 readyState/networkState 的数字及中文解释、暂停/定位、加载层、视频 CSS 可见性、临时静音保护和应用音量。应用音量不代表电视系统音量。
- 本机 MP4 就绪和文件大小只读取当前缓存文件；HTTP 状态仅来自该视频实际媒体请求的响应，不探测或重新请求视频。状态最多 24 个源、30 分钟过期、只存内存，保持原 Range 行为和媒体缓存容量。
- webOS 获取播放信息失败时，界面显示固定提示和错误码；诊断保留当前播放请求的阶段、上游 HTTP 状态、响应字节数、尝试次数和耗时。`VIDEO_MODEL_EMPTY` 表示播放信息接口返回空响应，尚未进入视频解码阶段；本机接口返回 502 不代表上游 HTTP 状态也是 502。预取和迟到请求不能覆盖当前播放失败的快照；独立 `/api/v1/diagnostics` 也只读当前前台准备结果，不读预取任务的最后结果。
- webOS 空响应的前台准备最多请求 3 次，两次间隔为 250ms、1000ms，与可重试的 HTTP/网络错误共用次数预算。独立预取只请求 1 次；前台接管尚未结束的预取任务时共用剩余预算。服务端处理过的失败不会再次触发页面自动刷新；手动重试开启新一轮。退出和取消会终止等待；这些间隔不是接口请求耗时上限，也不能修复长时间的上游故障。
- 诊断接口仅允许应用同源本机访问。输出不含账号、Cookie、完整播放 URL、媒体缓存标识、原始错误响应或设备唯一标识。视频错误只输出标准错误码，准备错误只保留允许的结构化字段。

诊断信息用于区分现象，并非自动确定根因。例如轨道为 `FORMAT_UNSUPPORTED_SUBTYPE` 表示设备没有接受该编码，`FORMAT_EXCEEDS_CAPABILITIES` 表示轨道超过设备能力；轨道为 `FORMAT_HANDLED` 且已选择、解码器已初始化但首帧未出，仍可能是解码器或视频层问题；“加载层撤下/宽高有效/解除静音”但用户仍反馈黑屏，则需要进一步核对设备画面显示和解码。

0.2.31 增加此只读工具，没有改变已有播放保护、解析、预下载或缓存策略。浏览器旧 API/布局模拟与 GitHub Android 构建不能代替反馈设备的实机验收。

## 播放准备失败（Android 与桌面）

`/api/v1/play/info` 的失败响应保留本机 HTTP 502 状态，但错误内容改为固定 `error` 代码、`stage` 和 `preparation` 结构。不会把原始 Go 错误字符串发给页面。诊断展示当前请求的准备错误；不读全局“最后一次失败”，不会被下一集预取覆盖。换集、账号切换及手动重试隔离旧结果，异步诊断读取也重新核对准备错误快照。

阶段包括 `device_register`（匿名播放身份注册）、`multi_video_model`（播放信息）、`fallback_api`（上游备用取源）、`source_select`（清晰度/兼容源选择）、`range_init`（首段 MP4 初始化）、`media_download`（整集下载）、`media_decrypt`（解密）、`cache_write`（缓存写入）；未分类内部错误为 `playback_prepare`。只有真实收到响应才记录上游 HTTP；未知状态省略，不用本机 502 填充。只有实际读完的接口响应才记录其字节数，0 字节与“未读取”区分。上游业务码只接收至多 16 位的数字字符串。

Range 与整集回退均失败时，主要诊断记录整集失败，并保留 `range_failure` 的代码、阶段及已知数值。诊断既不能据此断言解码失败，也不把 Range 回退认作设备身份切换。播放信息 `attempt` 为本次解析中实际取源请求次数（含一次身份替换前的请求，最多 6 次），`elapsed_ms` 为最后失败操作的耗时，不是各阶段总耗时。Range 与完整文件准备是各自独立解析，分别计数；没有累计成全局次数。

页面显示固定提示和错误码，不显示原始响应、Cookie、匿名设备 ID、完整签名 URL 或私有缓存路径。匿名身份恢复沿用已有规则：只有连续 HTTP 200 空体触发，单次解析最多更换一个匿名身份；本次诊断改动不增加重试、不增加切换提示，不改变播放引擎。webOS 独立 JS Service 的身份恢复与前后台共享预算见 [匿名播放身份与空响应恢复](playback-identity-recovery.md#webos-独立服务)。
