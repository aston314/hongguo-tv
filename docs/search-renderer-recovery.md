# 搜索建议切换与 WebView 渲染进程恢复

对应发布仓库 [Issue #121](https://github.com/aston314/hongguo-tv-releases/issues/121)。
报告设备为 TCL / 雷鸟 MT5879（MT9653）、Android 11 32 位、WebView
83.0.4103.120。报告者提供的堆栈显示渲染进程 SIGSEGV，随后宿主因未处理
renderer exit 退出；报告者的延迟切换补丁已通过其真机验证。本次按该证据
错开建议列表关闭和目标内容展示，同时补齐 Android 的恢复流程。

## 搜索建议

- 先关闭建议列表，再通过双 `requestAnimationFrame` 打开剧集详情、演员作品
  或提交关键词；缺少 rAF 时退回 80 ms 定时器。
- 等待期间重复确认不重复打开；返回、切页、修改输入和进入后台会取消。
- 执行前再检查页面、输入、建议代际、账号、前后台及详情/演员/扫码弹窗状态。
- 保留原建议 key 和搜索输入返回目标；关闭详情或演员作品后继续使用既有焦点恢复。

## Android 恢复

`onRenderProcessGone` 仅在 Android 8 / API 26 及以上生效，标准版和 MPV 版共用：

1. 将页面标记为失效，取消启动等待、输入编辑及按键路由，停止原生播放器和更新弹窗。
2. 清除 Activity 的 WebView 引用，将回调传入的失效视图移出父容器并销毁。
   不向它执行 JS、reload、stopLoading、pause 或 resume。
3. 返回 `true`；离开回调后才重新创建 Activity。后台退出的 renderer 等到前台再恢复。
4. 进程内每 60 秒最多自动恢复一次，预算跨 Activity 重建保留；短时间再次失败时
   显示原生“重试”按钮，允许手动重建，避免自动重启循环。

Go 服务不因 Activity 重建而停止，已有账号及本机记录沿用持久化数据。
不保证恢复渲染进程退出前尚未写入的播放位置，也不自动重试导致闪退的搜索选项。
Android 6/7 继续使用既有生命周期；前端切换时序和取消保护仍生效。

## 检查范围

- Node 行为测试覆盖两帧切换、剧名/演员/关键词、重复确认、返回取消、过期回调、
  输入/账号/页面/前后台变化，以及无 rAF 回退。
- Java 单元测试覆盖自动恢复预算及 60 秒边界，Android 两个 edition 的构建和 lint
  交由现有 GitHub CI 执行。
- 浏览器使用实际 UI 文件与本机 fixture API 验证详情/演员/关键词路径、逐帧展示顺序
  和返回焦点。fixture 不证明 Android 渲染进程恢复或受影响设备的 GPU 稳定性。
- 未在本机构建 APK，也未进行设备调试。本次实际 APK 在报告设备上的结果仍待验证。
