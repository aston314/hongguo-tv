# 同季下一集后台准备

标准版、MPV、桌面版和 webOS 共用同一套前端预取协调器，在当前集连续稳定播放后，只为同一详情中的紧邻下一集做一次播放准备；不跨集、不跨季，不同时准备多集，也不挂载第二个视频元素。默认策略是“边播边下”：标准播放保留 5 秒稳定窗口，MPV 缩短到 1 秒，各平台优先解析签名地址并建立 Range 索引。Android 标准版、Android MPV 版和桌面版还可以在设置中选择“整集预下载”；webOS 不显示该设置，也始终保持边播边下。

## 预取方式

- `边播边下（推荐）` 是默认值，也是 webOS 的固定值。预取请求使用 `mode=range&prefetch=1`，Range 准备失败时不会因为后台预取而转成整集下载；真正切集时仍沿用前台现有的 Range/完整文件回退逻辑。
- `整集预下载` 只改变后台下一集的准备方式，不改变当前播放器。当前集真正出现画面并连续稳定播放后才启动：Android 标准版和桌面版约 10 秒，MPV 约 12 秒。请求走现有完整文件解析、下载、解密和缓存任务，不新增第二套媒体缓存。
- 整集预下载只准备紧邻下一集，且协调器始终只有一个任务。任务未在切集前完成时，前台最多等待 1.2 秒；随后立即取消未完成的整集任务并按正常边播边下路径解析，不能无限等待。已经完成的本地文件可以直接交给播放器复用。
- 用户暂停、缓冲、拖动、切换清晰度、切剧、切账号、进入后台或离开播放页时，未完成的整集任务会取消；完整文件下载失败只结束后台任务，不阻塞当前播放。自然结束切集时保留已完成结果，交由下一集接管。
- Android 标准版、MPV 版和桌面版切到已完成整集预下载的紧邻下一集时，先沿用现有画面过渡，不立即显示中央 Loading 圆圈和集数。已经解码的下一集预览图按账号/剧/VID 精确匹配后直接复用，不等待统计接口再次返回，也不额外提取视频帧。自开始切集（包括自然连播查询详情）起超过 800 毫秒还未出画，才显示圆圈和“正在准备播放…”；首帧较早就绪则直接完成交接，不人为等待。800 毫秒只控制提示显示，不是播放超时或回退条件。
- 静默过渡必须通过与实际接管相同的清晰度、账号、播放模式、解码模式、VID 和缓存期限检查；预下载未完成、缓存校验失败或没有成功复用时恢复原有 Loading。快速再次切集、后台、退出、账号变化、播放失败及真实首帧完成会取消该代次的提示计时器。首次播放、换剧、非相邻集和 webOS 不启用这项过渡优化；现有首帧、遮罩和音频释放规则继续生效。
- 整集预下载会增加网络、存储和处理器占用。缓存仍使用现有 2 小时 TTL、512 MiB 单集上限和 512 MiB 完成文件清理机制；为了避免把接近过期的完整文件交给播放器，整集预下载结果的安全接管期限为 110 分钟，超过后会重新准备；MPV 采用更长的稳定窗口，避免下载/解密和解码同时抢占资源。

## 触发与范围

- 当前集已连续稳定播放后才触发；边播边下为标准播放 5 秒、MPV 1 秒，整集预下载为标准播放/桌面版 10 秒、MPV 12 秒。按真实经过时间判断，不按播放位置判断。历史续播、倍速、拖动到后段不会立即触发；暂停、缓冲、跳转后重新计算稳定时间。已经启动的同上下文任务继续复用。
- 页面可见、应用在前台且视频正在播放，清晰度切换期间不触发。
- 每次播放上下文只准备紧邻下一集。由汇总字段 `accessible_episode_cnt` 推导出的 `locked` 仅用于选集界面展示，不能证明上游播放接口一定拒绝该集；后台仍可尝试这一个 VID，由 `play/info` 作最终判断。若详情明确标记锁定、VID 无效或下一集缺失，则不发预取请求，绝不跨过该集继续找更远的 VID。
- 当前季最后一集不预备其他季，也不下载下一条推荐。
- 下一季确认、未上线预约和自然续播规则保持现有行为。

## 复用与取消

`ui/episode-prefetch.js` 保存单个可取消任务，按剧、当前 VID、集数、清晰度、播放代次和账号代次隔离。后台调用现有 `/api/v1/play/info`，带 `prefetch=1`。Range 预取失败只静默放弃，不会回退成整集下载；前台真正切集时重新请求，仍可自动切到完整文件准备模式。后台准备不改变当前视频地址、焦点或观看记录；完整预下载命中时的切集提示按上述 800 毫秒规则显示。

自然换集可以接管仍在等待详情或媒体准备的任务。预取结果在前台切集时直接作为播放源使用，避免同一个 VID 再次请求播放地址；如果预取尚未完成，前台最多等待 1.2 秒，随后走正常播放解析，迟到的预取结果不会覆盖当前播放。Range 模式复用内存中的初始化索引；整集模式只在文件已完成时复用本地路径，未完成任务会被取消。预取失败仅结束后台任务，实际换集仍会前台重试；MPV 和标准播放的前台 Range 准备失败均回退到现有整集下载/解密路径。

预取接管只服务于同一剧、相邻集、同一清晰度、播放代次和账号代次。切剧、手动跳集、清晰度改变、账号切换或离开页面会取消任务；因此它不会把旧剧的地址或缓存错误地交给新播放。

播放失败恢复也保持有界：标准 WebView/Media3 路径只自动刷新一次播放地址，仍失败就回到原有错误提示和手动重试；MPV 路径不自动重建原生会话，避免在部分设备上重复触发 Surface/解码器生命周期问题。

0.2.17 为同季自然下一集增加历史保存并行路径：ended 先提交本集完成记录，下一集的明确集号和起始位置不依赖这次写盘结果，因此不重复提交完成记录、不等待保存队列才解析或打开文件。写入继续按原队列顺序完成，下一集的播放记录排在本集之后，失败仍显示保存提示。只在原播放代次、账号代次、同剧相邻集、完成状态和已经读取历史均匹配时使用；首次播放、历史续播、手动选集及账号切换继续走原历史读取/等待路径。

切剧、选择不相邻的集、清晰度改变、切换账号、离开播放页面或进入后台时取消失效任务。前台接管后的任务仍由前台管理取消。准备被后台或账号切换中断时，保留可达的“重试播放”按钮，不自动抢占播放。

Go 按原有剧/VID/清晰度/回退策略缓存键共用准备任务。每个等待请求独立退出；最后一个等待者退出才取消下载。相同键的取消任务清理完成后才允许新任务写入，避免旧任务删除新文件。下载错误删除半成品；缓存失败和缺失文件均允许重试。

## 缓存及效果边界

webOS 针对 #59 增加独立策略：后台准备遇到可识别的网络错误、上游临时错误或 Range 暂不可用时，只有后续满足稳定播放条件的 tick 才会在间隔至少 3 秒后重试一次；暂停、取消、后台、账号/播放代次失效时不重试。明确的权限、登录、锁定、参数和非瞬态 4xx 错误，以及未知错误码都直接结束预取，不盲目重试。标准版、MPV、桌面版不自动重试预取。准备结果超过 2 分钟时不再直接接管。完整文件预下载另受 110 分钟安全接管期限约束；超过该期限即使文件仍在缓存目录，也重新走前台准备。长集在剩余 30 秒以内可提前刷新过期结果，与失败重试共用一次额外尝试的预算；仍过期时由前台重新解析。

webOS provider 的前台和预取请求共用相同 VID/清晰度/模式的取源与 Range 初始化任务。前台等待预取超过 1.2 秒后，正常解析仍能加入服务端在途任务，避免重复请求上游。Range 准备失败时只有前台允许整集回退；预取调用仍返回失败。服务端准备索引同样以 2 分钟为复用期限，过期重新取源。播放中的 Range URL 刷新和媒体一致性校验保持原机制。

针对 #70，撤掉 0.2.123 的第二个隐藏 video 与 DOM 替换接管方式。webOS 恢复连续稳定播放 5 秒后准备下一集，始终保留原来的唯一主视频元素及其监听器。Service 在 Range 索引可用后，最多预读开头 2 MiB，以 512 KiB 分块缓存解密后的字节；全局仅保留两个源（最多 4 MiB），闲置 2 分钟淘汰，预读总期限 5 秒。HTTP 播放请求直接读取这些分块，也能加入正在下载的同一块；只剩预取等待者时取消会中止下载，已有前台等待者时保留该块。预读失败保留已解析的片源，不额外触发整集下载，也不改动当前集的缓存会话。

webOS 取源最终返回临时错误时，页面使用现有的一次自动刷新预算恢复。它与视频 error 的自动恢复共享上限，不形成循环；权限/参数等明确错误不恢复，退出/后台/旧播放代次的错误不恢复。恢复使用目标集待播放位置，避免把上一集结尾时间带到下一集。其他平台的恢复策略不变。

webOS 播放诊断现在显示接口解析、Range 初始化、整集回退下载和解密的分段耗时，准备失败尚无媒体地址时也能读取最近一次前台准备的计时。已附加媒体通过适配器把本机绝对地址还原为精确的本地媒体路径，诊断不会因 file:// 到本机 HTTP 的地址改写而丢失当前源信息。缓存会话使用普通 CORS POST，兼容 Chrome 79 不支持跨域 keepalive 预检的限制。

保留现有 512 MiB 完成文件缓存清理阈值、2 小时 TTL 和 512 MiB 单集下载上限。一次最多新增一个后台准备任务；选择整集预下载时，下载中的文件和暂时被请求使用的文件可能让瞬时占用超过清理阈值。缓存清理继续按最近使用时间执行，不保存整季。

0.2.6 补齐重启后旧进程目录的回收，详见 [名称、导航与媒体缓存](navigation-and-cache.md)。旧版只有当前进程目录参与清理，不能据此保证跨重启总量不会累积。

解析和 Range 索引可提前完成；整集预下载模式还会在后台完成下一集的完整文件下载与解密，webOS 则按上述预算提前读取开头分块，其余媒体字节仍由当前播放器按需读取。无论哪种方式，视频解码和起播仍需要时间；网络慢、提前准备失败或刚开始播放便手动换集时，依然可能出现正常的播放 loading。预取只请求紧邻下一集，不跨集、不跨季。webOS 额外的开头缓存独立限制在 4 MiB 内。

- 完整预下载过渡补充回归：确认只读 readiness 与实际接管使用相同身份/期限检查；手动切集、自然连播、`waiting` 回调、快速再次选集、缓存失效、首帧完成、错误、后台及账号代次失效都不会遗留隐藏提示或旧计时器。浏览器 fixture 在 960×540、1280×720、1920×1080 验证预览图持续显示、800 毫秒后提示恢复、错误入口可见及首帧后的提示清理；这属于确定性 UI 验证，不代表实体设备已经完成实播验收。
- Node 测试覆盖稳定时间、一次触发、同季边界、迟到详情、账号/清晰度隔离、任务接管、静默失败和旧 WebView 兼容；新增播放流程测试让完成记录写盘保持未返回，验证下一集先起播、记录有序保存、不重复写完成状态、失败后仍能继续保存，以及退出后的迟到回复不绑定旧视频。
- Go race/vet 和全量测试覆盖准备任务共享、单消费者退出、最后消费者取消真实 HTTP 数据流、半成品删除、失败重试、缓存文件丢失及同键清理顺序。
- 隔离浏览器以模拟媒体时钟，在 1280×720、1920×1080 和缺失 fetch/AbortController/URLSearchParams 等旧环境验证换集、焦点、历史、切剧、清晰度、跳集、后台、账号变更和重试。没有请求真实账号写接口。
- APK 由 GitHub Actions 签名构建；实体 Android 6 换集延迟与长时间播放仍需设备复测。

## 0.2.17 隔离对比与计时

90 秒本机合成 MP4、相同的 2 秒完成记录写盘延迟、旧 API 与旧布局模拟条件下，0.2.16 自动换集出现两次完成写入，约 4029ms 后下一集 playing；0.2.17 只提交一次完成写入，约 14ms 后下一集 playing，完成记录当时仍在等待，随后本机历史正常更新为第2集。新预下载在播放约 5.5 秒时已开始。该对比证明写盘等待移出起播路径，不代表 Android TV 设备或真实网络会达到同样毫秒数。

预下载与完成写入同时失败的 fixture 中，正常播放接口仍解析并起播第2集，历史保存错误有提示，后续第2集记录保存成功。暂停 5 秒、恢复 3 秒以及缓冲后 3 秒均未启动新任务，恢复连续稳定 5 秒后只启动一次。

`window.HongguoTVPlaybackTiming.snapshot()` 提供最近最多 20 次成功起播的内存计时：集数、自动下一集标志、预取准备耗时、接管等待、前台解析、媒体源就绪、MPV 停止边界/`FILE_LOADED`/输出就绪和总耗时。核心诊断另列接口解析、Range 初始化，或整集下载/解密耗时。未包含剧名、ID 或账号信息，不落盘、不上传。MPV 的输出就绪不是硬件实际首帧时间。加载提示持续到播放器就绪事件，不用人为延迟。
