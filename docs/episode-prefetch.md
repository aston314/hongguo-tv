# 同季下一集后台准备

独立 TV APK 在当前集连续稳定播放后，检查详情中后续最多 4 个未锁定 VID，并只为紧邻的下一集做一次播放准备；不同时下载多集，不挂载第二个视频元素。标准播放保留 5 秒稳定窗口，MPV 缩短到 1 秒。两种路径都优先解析签名地址并建立 Range 索引，不下载整集。

## 触发与范围

- 当前集已连续稳定播放：标准播放 5 秒，MPV 1 秒；按真实经过时间判断，不按播放位置判断。历史续播、倍速、拖动到后段不会立即触发；暂停、缓冲、跳转后重新计算稳定时间。已经启动的同上下文任务继续复用。
- 页面可见、应用在前台且视频正在播放，清晰度切换期间不触发。
- 每次播放上下文只尝试一次。VID 候选最多向后检查 4 集，过滤 locked/不可访问集；只有紧邻下一集可播放时才准备它，不跨过锁定集自动跳集。
- 当前季最后一集不预备其他季，也不下载下一条推荐。
- 下一季确认、未上线预约和自然续播规则保持现有行为。

## 复用与取消

`ui/episode-prefetch.js` 保存单个可取消任务，按剧、当前 VID、集数、清晰度、播放代次和账号代次隔离。后台调用现有 `/api/v1/play/info`，带 `prefetch=1`。Range 预取失败只静默放弃，不会回退成整集下载；前台真正切集时重新请求，仍可自动切到完整文件准备模式。MPV 引擎保持不变。不改变当前视频地址、焦点、加载反馈或观看记录。

自然换集可以接管仍在等待详情或媒体准备的任务。预取结果在前台切集时直接作为播放源使用，避免同一个 VID 再次请求播放地址；如果预取尚未完成，前台最多等待 1.2 秒，随后走正常播放解析，迟到的预取结果不会覆盖当前播放。Range 模式复用内存中的初始化索引。预取失败仅结束后台任务，实际换集仍会前台重试；MPV 和标准播放的前台 Range 准备失败均回退到现有整集下载/解密路径。

预取接管只服务于同一剧、相邻集、同一清晰度、播放代次和账号代次。切剧、手动跳集、清晰度改变、账号切换或离开页面会取消任务；因此它不会把旧剧的地址或缓存错误地交给新播放。

播放失败恢复也保持有界：标准 WebView/Media3 路径只自动刷新一次播放地址，仍失败就回到原有错误提示和手动重试；MPV 路径不自动重建原生会话，避免在部分设备上重复触发 Surface/解码器生命周期问题。

0.2.17 为同季自然下一集增加历史保存并行路径：ended 先提交本集完成记录，下一集的明确集号和起始位置不依赖这次写盘结果，因此不重复提交完成记录、不等待保存队列才解析或打开文件。写入继续按原队列顺序完成，下一集的播放记录排在本集之后，失败仍显示保存提示。只在原播放代次、账号代次、同剧相邻集、完成状态和已经读取历史均匹配时使用；首次播放、历史续播、手动选集及账号切换继续走原历史读取/等待路径。

切剧、选择不相邻的集、清晰度改变、切换账号、离开播放页面或进入后台时取消失效任务。前台接管后的任务仍由前台管理取消。准备被后台或账号切换中断时，保留可达的“重试播放”按钮，不自动抢占播放。

Go 按原有剧/VID/清晰度/回退策略缓存键共用准备任务。每个等待请求独立退出；最后一个等待者退出才取消下载。相同键的取消任务清理完成后才允许新任务写入，避免旧任务删除新文件。下载错误删除半成品；缓存失败和缺失文件均允许重试。

## 缓存及效果边界

桌面版可在当前集完整缓冲后，额外准备最多 64 MiB 的下一集完整文件；仅接管已完成的文件，未完成时继续使用原有 Range 结果。该功能由桌面核心启动参数单独启用，Android 和 webOS 保留下述策略。资源、取消与合成测试详见 [桌面下一集完整文件缓存](desktop-episode-cache.md)。

webOS 针对 #59 增加独立策略：后台准备失败后，只有在后续满足稳定播放条件的 tick 中，间隔至少 3 秒重试一次；不在暂停或后台计时触发，不无限重试。准备结果超过 2 分钟时不再直接接管。长集在剩余 30 秒以内可提前刷新过期结果，与失败重试共用一次额外尝试的预算；仍过期时由前台重新解析。其他平台保留原有的重试次数和缓存寿命。

webOS provider 的前台和预取请求共用相同 VID/清晰度/模式的取源与 Range 初始化任务。前台等待预取超过 1.2 秒后，正常解析仍能加入服务端在途任务，避免重复请求上游。Range 准备失败时只有前台允许整集回退；预取调用仍返回失败。服务端准备索引同样以 2 分钟为复用期限，过期重新取源。播放中的 Range URL 刷新和媒体一致性校验保持原机制。

针对 #70，撤掉 0.2.123 的第二个隐藏 video 与 DOM 替换接管方式。webOS 恢复连续稳定播放 5 秒后准备下一集，始终保留原来的唯一主视频元素及其监听器。Service 在 Range 索引可用后，最多预读开头 2 MiB，以 512 KiB 分块缓存解密后的字节；全局仅保留两个源（最多 4 MiB），闲置 2 分钟淘汰，预读总期限 5 秒。HTTP 播放请求直接读取这些分块，也能加入正在下载的同一块；只剩预取等待者时取消会中止下载，已有前台等待者时保留该块。预读失败保留已解析的片源，不额外触发整集下载，也不改动当前集的缓存会话。

webOS 取源最终返回临时错误时，页面使用现有的一次自动刷新预算恢复。它与视频 error 的自动恢复共享上限，不形成循环；权限/参数等明确错误不恢复，退出/后台/旧播放代次的错误不恢复。恢复使用目标集待播放位置，避免把上一集结尾时间带到下一集。其他平台的恢复策略不变。

webOS 播放诊断现在显示接口解析、Range 初始化、整集回退下载和解密的分段耗时，准备失败尚无媒体地址时也能读取最近一次前台准备的计时。已附加媒体通过适配器把本机绝对地址还原为精确的本地媒体路径，诊断不会因 file:// 到本机 HTTP 的地址改写而丢失当前源信息。缓存会话使用普通 CORS POST，兼容 Chrome 79 不支持跨域 keepalive 预检的限制。

保留现有 512 MiB 完成文件缓存清理阈值、2 小时 TTL 和 512 MiB 单集下载上限。一次最多新增一个后台准备任务；下载中的文件和暂时被请求使用的文件可能让瞬时占用超过清理阈值。缓存清理继续按最近使用时间执行，不保存整季。

0.2.6 补齐重启后旧进程目录的回收，详见 [名称、导航与媒体缓存](navigation-and-cache.md)。旧版只有当前进程目录参与清理，不能据此保证跨重启总量不会累积。

解析和 Range 索引可提前完成；webOS 还会按上述预算提前读取开头分块，其余媒体字节仍由当前播放器按需读取，视频解码和起播仍需要时间。网络慢、提前准备失败或刚开始播放便手动换集时，依然可能出现正常的播放 loading。最多 4 集是 VID 候选窗口，不是 4 集媒体预下载。webOS 额外的开头缓存独立限制在 4 MiB 内。

## 验证

- Node 测试覆盖稳定时间、一次触发、同季边界、迟到详情、账号/清晰度隔离、任务接管、静默失败和旧 WebView 兼容；新增播放流程测试让完成记录写盘保持未返回，验证下一集先起播、记录有序保存、不重复写完成状态、失败后仍能继续保存，以及退出后的迟到回复不绑定旧视频。
- Go race/vet 和全量测试覆盖准备任务共享、单消费者退出、最后消费者取消真实 HTTP 数据流、半成品删除、失败重试、缓存文件丢失及同键清理顺序。
- 隔离浏览器以模拟媒体时钟，在 1280×720、1920×1080 和缺失 fetch/AbortController/URLSearchParams 等旧环境验证换集、焦点、历史、切剧、清晰度、跳集、后台、账号变更和重试。没有请求真实账号写接口。
- APK 由 GitHub Actions 签名构建；实体 Android 6 换集延迟与长时间播放仍需设备复测。

## 0.2.17 隔离对比与计时

90 秒本机合成 MP4、相同的 2 秒完成记录写盘延迟、旧 API 与旧布局模拟条件下，0.2.16 自动换集出现两次完成写入，约 4029ms 后下一集 playing；0.2.17 只提交一次完成写入，约 14ms 后下一集 playing，完成记录当时仍在等待，随后本机历史正常更新为第2集。新预下载在播放约 5.5 秒时已开始。该对比证明写盘等待移出起播路径，不代表 Android TV 设备或真实网络会达到同样毫秒数。

预下载与完成写入同时失败的 fixture 中，正常播放接口仍解析并起播第2集，历史保存错误有提示，后续第2集记录保存成功。暂停 5 秒、恢复 3 秒以及缓冲后 3 秒均未启动新任务，恢复连续稳定 5 秒后只启动一次。

`window.HongguoTVPlaybackTiming.snapshot()` 提供最近最多 20 次成功起播的内存计时：集数、自动下一集标志、预取准备耗时、接管等待、前台解析、媒体源就绪、MPV 停止边界/`FILE_LOADED`/输出就绪和总耗时。核心诊断另列接口解析、Range 初始化，或整集下载/解密耗时。未包含剧名、ID 或账号信息，不落盘、不上传。MPV 的输出就绪不是硬件实际首帧时间。加载提示持续到播放器就绪事件，不用人为延迟。
