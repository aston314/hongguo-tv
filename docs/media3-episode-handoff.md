# Prepared Media3 episode handoff

When the current episode is using Media3 and the next episode's codec is explicitly unsupported by HTML5, the existing episode prefetch result can also prepare approximately 1.5 seconds of Media3 samples. A timeout fallback or an unknown codec declaration does not establish this eligibility. Supported and uncertain HTML5 sources retain the existing player selection, including the existing fallback behavior. MPV and live playback do not use this preloader.

The preloader shares Media3 components with one ExoPlayer. It does not create another player or start a second decoder. It holds the playing source and at most one pending source. Pending preparation has a 10-second timeout and a 120-second lease, and is discarded on cancellation, navigation or backgrounding. Source URL, key, zero start position and primary candidate must match before adoption. If adoption fails before the first frame, the player may retry the same source once without the speculative MediaSource, then follow the existing candidate/error handling.

For a confirmed, prepared adjacent episode, the UI can keep the native route connected during source replacement and avoid redundant hidden HTML5 loads and title updates. History remains in its ordered save queue; an already loaded library and an explicit zero-position adjacent handoff need not wait for its pending write. Other navigation and resume paths retain the existing gate. Native player configuration changes rebuild the player, and a real exit releases a suspended instance after a bounded two-second lease.

Presentation still requires the current source/session, a rendered frame, an advancing media clock and valid playback state. A ready native handoff checks its real position every 50ms after the first frame until advancement is observed, for at most one second, then returns to 500ms reporting. Only this confirmed path uses a 50ms cover guard after the compositor paint boundaries; ordinary native transitions retain 200ms. Pausing, buffering, backgrounding, failure or replacing the source invalidates presentation callbacks and keeps audio protection.

For a ready adjacent source, loading feedback is deferred up to 800ms from switch initiation. A completed transition reveals immediately; it never waits for this deadline or a minimum spinner duration. Unprepared sources keep existing loading feedback and errors remain immediate. This is a presentation choice, separate from playback performance.

Validation should cover repeated adjacent handoffs, a supported HTML5 source, unknown codec support, cold entry, nonzero resume, quality changes, rapid selections, paused/background transitions, preloader failure and decoder configuration changes. Existing diagnostics remain scoped to the active playback identity. The change does not alter source-request retries, anonymous identities, upstream response handling or account behavior.
