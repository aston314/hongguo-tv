# 繁体片名与简介

界面语言为 zh-TW 时，共享 WebView 在写入文字节点前，将上游片名、简介和系列列表副标题按
OpenCC 1.4.2 s2twp 转换。Android、桌面与 webOS 共用同一显示层。
静态 UI 继续使用现有繁体语言文件；简体和日语模式不读取词库。

转换只作用于显示，不修改 API 对象、播放 ID、收藏、观看历史或账号同步。
搜索请求、用户输入、搜索历史、弹幕和评论原文不转换。
独立演员姓名字段保持原文；简介中人名仍可能有官方词库本身的歧义，
例如“于和伟”可能显示为“於和偉”。始终从原始字段转换，禁止转换已显示的文本。

## 本地资源与生成

词库随应用打包，读取相对于 UI 文档的 chinese-content 资源，不依赖 CDN、
翻译服务器、账号或远程 JS 规则。webOS 从安装包的 file:// 资源读取。

原始数据在 third_party/opencc，固定官方 ver.1.4.2：
https://github.com/BYVoid/OpenCC/tree/ver.1.4.2

压缩文本由官方同版本 opencc_dict 从 .ocd2 导出。生成器核对源文本 SHA256，
保留完整词组、默认候选、分词与字典优先级，并在构建时生成只读连续索引，
避免在运行时逐词创建大量 Map/Object。生成器不需要联网或原生 OpenCC 环境：

    python3 scripts/build_chinese_content.py
    python3 scripts/build_chinese_content.py --check

生成文件提交在共享 UI 的 chinese-content 目录。CI 检查生成结果；
Go 嵌入资源测试和 webOS staging 检查分别确认资源与许可证随包提供。
LICENSE 和注明导出/索引修改的 NOTICE 与词库一同分发。

## 显示生命周期

繁体模式在 UI 模块启动时并行准备词库和其他界面初始化。
尚未就绪的新文字节点暂不显示简体，词库就绪后只更新绑定的文字与辅助标签，
不重建列表、不改变焦点、不发播放请求。现有语言设置仍沿用原有整页重载流程。
资源读取有超时；失败后显示原文，同一页面生命周期不按节点反复重试。

绑定使用元素自身的原始字符串引用；没有全局节点列表或 MutationObserver，
已移除的节点可以正常回收。只在词库就绪或语言变化时查询已绑定元素，
焦点移动与播放帧回调不扫描页面或触发词库加载。
同一个元素的内容被其他渲染逻辑替换后，延迟回调不会把旧片名写回来。

转换结果缓存最多 256 项，原文和结果合计不超过 65,536 个 UTF-16 单元。
超过 8,192 字符的单个字段保留原文；不截断显示内容。
切回其他语言时取消在途读取、释放转换器与缓存，并恢复原文。

## 验证边界

官方 s2twp 85 例和金标准文本在仓库内持续回归。
接入前，57,153 条输入分别在当前 JS、Node 0.12、Node 8 与官方 C++ 1.4.2
对照一致；Shield 独立 WebView 完成词库与文字渲染计时。
这些结果不替代旧盒子/LG 实机的完整播放与长期内存验收。
紧凑索引约 1.43 MiB 是数据大小，不是应用进程内存增量。
