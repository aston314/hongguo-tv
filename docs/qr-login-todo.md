# 扫码登录 TODO

## 目标

在保留现有手机号验证码登录的前提下，增加“手机红果 App 扫码确认登录”。两种方式登录成功后使用同一套账号状态、账号目录、云同步、搜索和播放链路。

已完成的协议验证：扫码确认后可以取得有效账号会话；登录态 App 搜索“借势千秋”返回可播放结果；结果中的视频可以进入现有播放解析链路。正式接入前仍需完成应用内持久化和失败状态验收。

## 范围

- [ ] Android 标准版、Android MPV 版、桌面版接入扫码登录。
- [ ] 手机号验证码登录保持现有接口、字段和交互不变。
- [ ] webOS 暂不直接复用本项实现；如需支持，另按 webOS 服务层单独移植。
- [ ] 扫码登录只负责账号登录，不在本阶段新增点赞、收藏、预约或评论功能。

## Go 核心

### 接口

- [ ] `POST /api/v1/account/qr/start`：创建一次性扫码会话并返回二维码图片、会话状态和过期时间。
- [ ] `GET /api/v1/account/qr/status`：返回 `preparing`、`pending`、`scanned`、`processing`、`signed_in`、`expired`、`cancelled` 或 `failed`。
- [ ] `POST /api/v1/account/qr/cancel`：取消当前扫码会话，停止轮询。
- [ ] 扩展 `GET /api/v1/account` 的状态字段，让页面能区分当前登录方式和扫码状态。

### 扫码状态机

- [ ] Go 侧请求官网二维码接口，页面只接收二维码图片，不接触 Cookie、token 或跳转凭证。
- [ ] 每约 1.8 秒轮询确认接口；二维码默认有效期约 180 秒，过期后允许重新获取。
- [ ] 处理“待扫码、已扫码待确认、已确认、已过期、取消、网络失败”全部状态。
- [ ] 登录代际递增：旧轮询完成后不得覆盖新二维码、新登录或已退出的账号。
- [ ] 取消、退出页面、应用进入后台或重新获取二维码时，释放旧轮询和 Cookie Jar。
- [ ] 仅允许跳转到 `hongguoduanju.com` 及其子域名，拒绝其他跳转地址。

### 账号落盘与共用逻辑

- [ ] 扫码确认后获取 UID，创建独立设备身份并完成设备注册。
- [ ] 将网站会话 Cookie、设备 ID、安装 ID、注册状态和 UID 原子写入现有 `account.json`。
- [ ] 扫码登录复用手机号登录的收尾逻辑：创建账号目录、切换 `store`、保留本机记录、启动云同步。
- [ ] 不改变现有 `accountDisk` 版本和手机号账号文件的读取兼容性。
- [ ] `profile.phone` 允许为空；增加可选 `login_method: "qr" | "phone"` 仅用于显示和诊断，不作为鉴权条件。
- [ ] 当前已有账号时不能静默覆盖；要求先退出或明确确认切换账号。
- [ ] 退出账号时清理扫码会话，不把二维码 token 或账号 Cookie 写入日志和页面错误文本。

## 页面与焦点

- [ ] 账号页增加“手机号登录 / 扫码登录”切换控件，默认保留现有手机号页面。
- [ ] 扫码页显示二维码、有效期、当前状态、“重新获取”和“取消”按钮。
- [ ] Android TV 使用明确的 D-pad 焦点顺序：登录方式 → 二维码状态 → 重新获取 → 取消。
- [ ] 返回键在扫码页只取消/关闭扫码流程，不退出应用；成功后焦点回到账号页的账号操作区域。
- [ ] 桌面版支持鼠标和键盘操作，二维码尺寸在小视口和大视口均有稳定上限。
- [ ] 补齐当前支持的简体中文、繁体中文和日文文案。
- [ ] 扫码成功后自动刷新账号页，不要求用户手动重进页面。

## 非目标与风险

- 本阶段不把扫码登录凭据复制到前端 JavaScript，也不保存二维码原始 token。
- 播放能力本身通常使用独立的匿名播放设备身份；扫码账号主要影响搜索、历史、收藏、预约和互动接口，不能把二者混为一个播放器会话。
- 上游二维码、账号 Cookie 和接口状态可能变化；遇到登录成功但某个写入接口返回业务错误时，应显示明确错误，不自动重试造成重复写入。
- 浏览器验证只能证明核心接口和媒体文件可用，不能替代 Android 实机首帧、遥控焦点和不同解码器验证。

## 实施顺序

2. [ ] 账号页扫码 UI、焦点和多语言。
3. [ ] 真实扫码登录、搜索、历史/收藏/预约读取和播放回退验证。
4. [ ] 手机号登录与账号同步回归。
5. [ ] 提交并整合到统一主线，再决定是否发布各平台版本。

## 本轮实施状态（2026-10-30）

- 修改前已同步 `origin/main`，起点为 `3a97ec6`；不使用 Documents 目录的旧分支作为实现基础。
- Android 标准版、MPV 版和桌面共用 Go 扫码协议与账号页；默认手机号登录不变，webOS 隐藏扫码入口且不新增服务接口。
- 刷新取码串行化，每次创建固定返回自己的本地 ID；取消只作用于匹配 ID，旧确认结果不能覆盖后续登录。
- Cookie Jar 仅在 Go 中使用；核验 UID、注册独立设备成功后，复用手机号登录的事务保存账号，失败不写入账号。
- 网络中断可在有效期内恢复；手机已确认后另有 45 秒完成期限，避免二维码临近过期时误取消账号保存。
- Go fixture 覆盖确认、刷新、取消、过期、恶意跳转、持久化、旧手机号文件及现有收藏写接口；fixture 不等于真实账号验证。
- 本机不编译。Go 测试、race 和 Android 两版本构建由 GitHub Actions 执行；`Core browser preview` 工作流可提供指定平台的临时预览核心，不发布正式版本。
- 集成版真实扫码、重启恢复及 Android 6 遥控操作仍须验收；先前独立测试页的结果不直接计入集成版验收。
