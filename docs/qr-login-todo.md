# 扫码登录 TODO

## 目标

在保留现有手机号验证码登录的前提下，增加“手机红果 App 扫码确认登录”。两种方式登录成功后使用同一套账号状态、账号目录、云同步、搜索和播放链路。

集成版已完成真实扫码确认、账号保存、重启恢复，以及登录态搜索、历史、收藏、预约列表和视频 Range 请求验证。Android 实机验收仍待进行。

## 范围

- [x] Android 标准版、Android MPV 版、桌面版接入扫码登录。
- [x] 手机号验证码登录保持现有接口、字段和交互不变。
- [x] webOS 使用独立 JS Service 扫码适配，复用共享页面和相同本地接口，不依赖 Go 核心。
- [x] 扫码登录只负责账号登录，不在本阶段新增点赞、收藏、预约或评论功能。

## Go 核心

### 接口

- [x] `POST /api/v1/account/qr/start`：创建一次性扫码会话并返回二维码图片、会话状态和过期时间。
- [x] `GET /api/v1/account/qr/status`：返回 `preparing`、`pending`、`scanned`、`processing`、`signed_in`、`expired`、`cancelled` 或 `failed`。
- [x] `POST /api/v1/account/qr/cancel`：取消当前扫码会话，停止轮询。
- [x] 扩展 `GET /api/v1/account` 的状态字段，让页面能区分当前登录方式和扫码状态。

### 扫码状态机

- [x] Go 侧请求官网二维码接口，页面只接收二维码图片，不接触 Cookie、token 或跳转凭证。
- [x] 每约 1.8 秒轮询确认接口；二维码默认有效期约 180 秒，过期后允许重新获取。
- [x] 处理“待扫码、已扫码待确认、已确认、已过期、取消、网络失败”全部状态。
- [x] 登录代际递增：旧轮询完成后不得覆盖新二维码、新登录或已退出的账号。
- [x] 取消、退出页面、应用进入后台或重新获取二维码时，释放旧轮询和 Cookie Jar。
- [x] 仅允许跳转到 `hongguoduanju.com` 及其子域名，拒绝其他跳转地址。

### 账号落盘与共用逻辑

- [x] 扫码确认后获取 UID，创建独立设备身份并完成设备注册。
- [x] 将网站会话 Cookie、设备 ID、安装 ID、注册状态和 UID 原子写入现有 `account.json`。
- [x] 扫码登录复用手机号登录的收尾逻辑：创建账号目录、切换 `store`、保留本机记录、启动云同步。
- [x] 不改变现有 `accountDisk` 版本和手机号账号文件的读取兼容性。
- [x] `profile.phone` 允许为空；增加可选 `login_method: "qr" | "phone"` 仅用于显示和诊断，不作为鉴权条件。
- [x] 当前已有账号时不能静默覆盖；要求先退出或明确确认切换账号。
- [x] 退出账号时清理扫码会话，不把二维码 token 或账号 Cookie 写入日志和页面错误文本。

## 非目标与风险

- 本阶段不把扫码登录凭据复制到前端 JavaScript，也不保存二维码原始 token。
- 播放能力本身通常使用独立的匿名播放设备身份；扫码账号主要影响搜索、历史、收藏、预约和互动接口，不能把二者混为一个播放器会话。
- 上游二维码、账号 Cookie 和接口状态可能变化；遇到登录成功但某个写入接口返回业务错误时，应显示明确错误，不自动重试造成重复写入。
- 浏览器验证只能证明核心接口和媒体文件可用，不能替代 Android 实机首帧、遥控焦点和不同解码器验证。

## webOS 接入（2026-10-30）

- 基于已整合的 `origin/main` 提交 `f8bdcc0` 开始实现；上节“webOS 不接入”仅描述首批范围，本节扩展到 webOS。
- Service 内执行官网取码、确认轮询、HTTPS 域名/路径作用域 Cookie、跳转、UID 核验及独立 App 设备注册；页面仅取得本地随机会话 ID、PNG 和显示状态。
- 复用现有账号文件、账号目录、预约/追更/互动接口和云同步。文件版本不变，旧手机号账号默认显示为手机号登录；新扫码账号保存可选 `login_method: "qr"`。
- 默认扫码且入口位于手机号之前，Service 能力字段控制显示；旧 Service 没有扫码能力时继续显示手机号入口。
- 刷新、返回、切换手机号、后台和 Service 关闭取消旧扫码；请求超时 12 秒，待确认按官网有效期，手机确认后有独立 45 秒完成期限。网络暂时失败在有效期内串行重试，过期不自动重新取码。
- 账号保存成功前不替换游客账号；取消后的迟到确认、短信/MFA 响应及旧账号同步都不能覆盖新账号。
- 自动化覆盖完整扫码保存/恢复、现有预约接口凭据复用、刷新/取消/过期/断网、Cookie 作用域、跳转限制、坏图片/UID/设备注册、保存失败、短信/MFA 兼容、HTTP 方法/ID/大小限制和 Service 关闭。
- webOS Service 本地真实环境已完成用户扫码确认、云端历史/收藏同步，以及进程重启后同账号恢复；记录只核对身份哈希，不在文档中保存身份和凭据。真实登录不等于 LG 电视运行时已验收。
- 真实只读验收发现预约读取返回 HTTP 200 空响应；同一扫码会话交给 Go 核心可正常读取，排除扫码凭据本身失效。原 webOS 签名器有两处与 Go 不一致：无请求体 GET 发送空的 `X-SS-STUB`，以及 Medusa 的 XMXOR 使用头部两字节计算 flag，Go 使用尾部两字节。移除空头后曾成功但仍有空响应，完整 Medusa 向量比对定位到第二处错误；修正后完整签名与 Go 现有固定向量一致。增加完整签名和空请求体回归测试，播放生命周期未改动。
- 本轮不发布 IPK；LG 电视实际扫码确认、重启恢复和遥控操作仍需实机验证。
