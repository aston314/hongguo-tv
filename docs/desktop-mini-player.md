# 桌面小窗播放

macOS、Windows、Linux 桌面版在播放控制区提供“小窗播放”。进入后，同一个主窗口切换为置顶小窗，沿用现有 WebView 和视频节点，不重新获取播放地址或重启播放。

- 支持暂停/播放、上一集/下一集、进度和音量调节。
- 桌面版设置提供“小窗隐藏系统标题栏”，默认关闭。开启后通过小窗顶部拖动，边缘仍可调整大小；悬停时顶部的“恢复系统标题栏”按钮可立即回到原样。设置只保存在本机，不影响 Android 或 webOS。
- 隐藏标题栏失败时保留现有小窗，并关闭这项设置。返回大窗前先恢复系统标题栏，再恢复原来的窗口尺寸与全屏状态；切换过程不替换 WebView 或视频节点。
- 从推荐进入时，可以切换上一部/下一部；独立剧集播放时禁用这两个按钮。
- 点击右上角返回按钮或按 Escape 返回大窗，恢复进入前的位置、大小及全屏/最大化状态。
- 保留用户调整过的小窗大小和位置，退出应用再打开也会恢复；显示器配置改变时重新居中。
- macOS 单独保存进入原生全屏前的窗口尺寸和最大化状态，等待全屏动画完成后再切换小窗，返回全屏再按 Escape 时恢复原窗口。恢复的小窗会限制在显示器可用区域内。
- 最小化仍按现有规则暂停，恢复后保留小窗模式。原生关闭按钮仍按原有退出确认流程处理。

Linux 的置顶效果取决于窗口管理器。窗口大小以操作系统窗口坐标计算；首开竖屏约 320×568，横屏约 480×300，可以手动调整。

验证分层：共享交互与状态隔离测试、窗口控制器竞态测试、真实数据浏览器切集/切剧、macOS 原生窗口模式验证，以及 GitHub Actions 的 macOS/Windows 构建和 Linux AppImage 播放检查。浏览器测试不代表所有桌面系统的编解码能力。

小窗配置保存在桌面应用数据目录的 `mini-player-window.json`，只记录几何信息和显示器配置，不记录播放内容。配置缺失或损坏时使用默认小窗。直接从小窗退出应用时也保存，普通主窗口或全屏尺寸不会覆盖小窗尺寸。

macOS 原生回归检查：在 `desktop` 目录运行 `HONGGUO_TEST_NATIVE_FULLSCREEN=1 go test -run TestNativeWindowRestoration -v .`，会打开临时 Cocoa 测试窗口并验证普通/最大化窗口的“全屏 → 小窗 → 全屏 → 退出全屏”往返。默认 `go test` 验证通知时序、原始尺寸恢复和坐标越界处理，不自动切换桌面 Space。
