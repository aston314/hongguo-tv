# webOS 在线播放规则宿主

webOS 复用同一份签名清单、不可变 JS、公钥、控制 revision 和公告操作。首次接入需要更新应用；之后在现有宿主能力内的规则修复可走同一静态发布通道。当前仍默认关闭。

## 实现与信任

- `playback-rule-trust.js` 由正常生成器生成，仅包含公钥和四条公开自测向量；`-check` 防止与 Go 漂移。
- 规则经过 Ed25519、canonical-S、规范化 payload、时效、递增 revision、protocol/host API、精确分发目录、大小和哈希检查，不接受任意执行 URL。
- 清单和脚本原子写入，保留已验证回滚版本和独立最高控制版本。缓存文件损坏不丢掉签名高水位；控制存储损坏时回到原有 provider。
- 本地关闭保留缓存；远程停用和再次恢复均需更高 revision 的签名控制。公告反映实际活动 revision，不改变用户选择。

## 执行与资源

下载代码只在单独 Node 子进程内执行，避开账号／媒体服务的事件循环；不继承账号环境、Inspector 或 Node 启动参数，不提供账号 Cookie、文件服务或播放器 API。私有字节适配处理 Node 0.12 Buffer 布局差异，不修改主服务 Buffer 原型。

一个活动进程复用规则和匿名身份；更新时最多加一个验证候选。父进程串行处理受限 HTTP。单次修复最多占原有 30 秒取源预算的 8 秒，档位不可用或媒体失败后继续原有来源。关闭、超时、异常、服务 shutdown 和父进程断开均具备退出路径；取消不能把规则误标为坏版本。

Node `vm` **不是敌对脚本安全沙箱**。子进程用于事件循环和生命周期隔离，只运行维护者签名代码；签名权威被攻破不在此隔离承诺内。48 MiB V8 old-space 限制**不是进程 RSS 硬上限**。实际 LG 权限、额外内存和长时间播放仍需电视验收。

## 验证层次

`tests/webos-playback-repair.test.cjs` 覆盖验签、坏更新、回滚、高水位、缓存、启停、取消清理和仅限本机的设置操作，并用真实 Node 0.12／8 执行同一 bundle、自测向量和进程 IPC。CI 旧运行时矩阵执行这些测试，打包检查确保工作进程、信任数据及依赖许可进入 IPK。

真实上游测试逐样本确认 `preparation_timing.media_resolver` 为 `signed-js` 后，再读取解密媒体。原生回退成功、只有模型或 HTTP 200 都不能当作 LG 真机播放验收。旧 Node 的证书问题应与规则验签、取源、媒体读取分开记录；不得为使测试成功关闭 TLS 验证。

2026-11-24 的本机验证：真实 Node 0.12／8 均加载同一规则并通过四条签名向量、精确 ID、备用 V5 域、ByteVC2 兼容回退及子进程复用／清理。两个运行时均从稳定通道下载 revision 1／`2026.11.24.1`，两个真实样本均确认走 `signed-js`，各读取 1 MiB 解密 MP4。Node 0.12 最初在媒体读取遇到 `SELF_SIGNED_CERT_IN_CHAIN`，原有 provider 对照也复现；查明为原六域补丁未覆盖动态 reading-video CDN，且 Range 未调用辅助函数。核实三条实际边缘域的 G2 证书链，补齐受限域族与 Range 接入后，同样本重测通过；未放宽 TLS 验证。此证据不能替代实际 LG 进程权限、额外内存、首帧与连续播放验收。
