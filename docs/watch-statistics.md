# 本机观看统计

入口：历史 → 观看统计。Android 标准版、MPV、桌面端共用 UI 与采集器；webOS 使用同一 HTTP 合同和独立异步存储。

- 显示今日、本周（周一至今）、本月时长，最近七天趋势，以及本月内容类型、主要题材列表（完整排序，可滚动）。
- 趋势与观看偏好上下排列，各占一行；偏好显示当前分类总项数，通常可见约5～6行，矮视口约4行，超出后滚动。保留全部条目与内容类型/题材切换，遥控器从趋势向下进入偏好、向上返回趋势，逐项移动时保持焦点可见。
- 仅题材偏好使用多列：宽视口（大于1200 CSS px）4列，761～1200为2列，较窄视口1列；内容类型维持单列。列表高度上限和比例条样式不变，按观看时长从左到右、从上到下排序。遥控器根据实际位置左右换项、上下换行，首行向上回当前分类，首列向左回侧栏，右侧和底部边界不跨行。
- 以播放时钟确实前进的真实经过时间计时；倍速不放大观看时长。暂停、等待、拖动、后台、失效播放会话不计入。超过五秒的无回调间隔不补算，避免把休眠算成观看。
- 不重建旧观看时长，不上传云端。游客及每个账号分开；仅在当前设备保存。
- 优先使用播放条目已有标签，包括推荐首集 category_schema 的题材名称；不把榜单、热度等推荐徽标当题材。卡片、搜索、历史等入口还复用播放器既有互动统计请求的分类字段；数字类型 1 记作真人，1004 记作漫剧，明确 ai_video 时优先记作 AI 剧。只有标签缺失时，统计提交队列才在后台读详情补齐，最多等待两秒，绝不让播放/切集等待。主要题材取第一个有效题材标签，缺失时保留未分类；不从标题推断，也不把同一分钟重复分配到多个题材。
- 统计独立于 library.json，按日聚合、保留最近366日，每日最多4类内容/16类题材。不保留剧名、逐集记录、播放位置、媒体地址和账号凭据。
- 每30秒或离开播放时异步提交，批次 ID 去重；网络故障的内存队列有上限。突然断电或系统杀进程可能丢失最后一小段未提交时长，这项轻量统计不以阻塞播放换取账务级精确性。
- 服务端使用原子替换，不对统计执行 fsync；webOS 的读写使用异步 fs API。统计文件损坏/写入失败只影响统计，界面提供重试。
- 统计与清空观看历史独立；清空进度列表不重置统计。时间按设备当地日期分桶，跨午夜分开累计。
- 右上角「重置统计」使用已有确认弹窗，默认聚焦取消；只清除当前设备、当前用户的统计，保留历史、进度及其他用户。成功后立即显示新的记录起点（当地日期及小时、分钟），重启后保留；取消或写入失败不替换当前统计。Go 与 webOS 均原子保存新的统计代次，拒绝重置前迟到的提交；采集器串行等待当前提交并丢弃该用户的旧队列，不让旧数据重新出现。新会话首次提交前读取一次代次，后续批次复用，不增加逐帧或逐集请求。

验证包括采集器的暂停/倍速/拖动/后台/换集/账号切换/跨午夜、HTTP身份校验/重试去重、并发保存、保留期及分类数量上限、webOS存储合同、多语言/遥控器返回和不同视口排版。浏览器验证不能替代全部电视型号的长期实机播放测试。
