# 本机播放记录请求校验

“本机记录未保存：记录请求无效”原先只表示 `/api/v1/library` 的第一轮 JSON 解码失败，不能据此判断为磁盘故障、扫码登录失败或云端历史写入失败。账号归属不匹配另行返回“账号已切换”。安卓标准版、MPV 版和桌面版共用此 Go 接口；webOS 使用独立 JS 服务。

当前处理：

- 页面发送记录前，将简介限制为 1000 个 Unicode 字符、标签限制为 8 项，与服务端原有保存规则一致。旧实现只在服务端解码成功后裁剪，较长详情可能先触发 32 KiB 请求上限。详情原文、选集数据、播放位置和完整字符串 ID 均保留。
- 评分统一为字符串后再保存。榜单雷达的 `growth.score` 为数字，官方榜和飙升榜均会将它带入播放；详情的空评分使用 `omitempty`，合并时不会覆盖榜单数字，原样提交便触发 `LIBRARY_FIELD_TYPE / drama.score`。共享页面的 `basicDrama` 将有限数字转成字符串，已有字符串原样保留，缺失或异常的可选评分不写入。历史、收藏、点赞和继续观看复用这条边界；不修改原榜单和播放详情，不放宽 Go 校验。
- Go 接口继续严格校验，不放开未知字段，也不扩大请求上限。失败区分 `LIBRARY_REQUEST_TOO_LARGE`（413）、`LIBRARY_FIELD_TYPE`、`LIBRARY_FIELD_UNKNOWN`、`LIBRARY_REQUEST_INVALID` 和 `LIBRARY_REQUEST_TRAILING`（400）。类型错误可返回已知 schema 字段路径，不返回请求内容或任意未知字段名。
- 拒绝的请求不修改记录；保存失败仍显示提示，后续保存可以继续。账号归属校验、云同步队列和播放器行为保持原有规则。

验证包含真实页面函数生成的超长详情请求、普通元数据保真、榜单评分与缺评分详情合并后的历史/收藏/点赞请求（游客与账号）、异常可选评分、失败后继续写入、Go HTTP 严格校验与边界、记录重启恢复，以及扫码登录成功后的本机进度写入。

电视截图明确报出 `drama.score`，已复现榜单数值评分触发同一拒绝的路径。仅凭截图不能确定用户的具体播放入口或原始评分值，也不能将所有记录失败归因于评分；其他错误继续按具体字段定位。

2026-11-11 本地 Go 服务与浏览器实测：从榜单雷达的真人榜进入《小镇是非多之同床异梦》，榜单评分为数字 `7.9`，真实详情不含 `score`。实际播放后，页面提交的进度和收藏请求均为字符串评分，HTTP 200；直接重放原数字评分请求则为 HTTP 400 / `drama.score`。重启本地服务后，评分、集数、33.44208 秒进度和收藏状态完整读回。该测试验证记录链路，不替代 Android 实机播放验证。
