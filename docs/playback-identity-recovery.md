# 匿名播放身份与空响应恢复

## 问题证据

2026-10-31，[公开反馈 #109](https://github.com/aston314/hongguo-tv-releases/issues/109)
在同一进程、同一视频上进行匿名身份 A → B → A → B 的对照：A 两次取得片源，
B 两次都是 HTTP 200 空响应。它支持“取源结果与身份相关”，尚不能确定上游原因、
身份有效期或认定全部空响应都由身份造成。

此阶段尚未取得媒体 URL，与 MPV/Media3 的解码错误分开处理。

## 请求与恢复规则

- 播放身份独立于登录账号，通过匿名 `POST /service/2/device_register/` 注册；
  不读取账号 Cookie、Token，也不改动登录状态。仍仅在当前核心进程内缓存。
- 取源仍使用 `POST https://api5-normal-sinfonlineb.fqnovel.com/novel/player/multi_video_model/v1/`，
  沿用现有请求参数、清晰度/codec 策略及媒体缓存。
- 同一身份最多尝试 3 次。只有连续收到 HTTP 200 且响应体为空（包括纯空白）
  才尝试刷新身份；任一请求成功就直接使用结果。
- 每次取源最多采用一次替换身份。替换后沿用最多 3 次的空响应重试；仍失败就
  返回错误，不能递归换身份或无限重试。因此单次取源最多 6 次播放接口请求，
  正常成功路径不增加请求。
- HTTP 非 200、网络/读取错误、超时、业务错误、无效 JSON、缺少模型、codec
  筛选后没有可用源、媒体下载/解密/解码失败，都不触发身份刷新。

## 并发、取消与失败边界

- 前台播放、下载和预取共享注册/刷新中的任务。并发旧身份失败只发起一次刷新；
  刷新期间新来的请求等待同一个结果，迟到的旧身份失败直接复用已有替换身份，
  不能再次覆盖它。
- 两次刷新发起时间至少间隔 30 秒，注册失败也计入间隔。它是本地防止注册风暴
  的保护间隔，不代表上游身份有效期；间隔结束后允许后续请求再次恢复。
- 刷新成功后复用新身份；刷新注册失败保留原身份，避免将可用缓存清空。
- 请求取消后可立即退出等待，不再发起后续取源请求；共享注册使用自己的 8 秒
  超时，一个请求取消不能中断其他请求需要的注册。
- 诊断日志只记录刷新动作及既有的空响应状态、长度、上游 logid，不记录设备
  身份三元组、账号凭据、签名或完整媒体 URL。

## 验证

`minireel_identity_recovery_test.go` 用本地 HTTP fixture 验证坏身份换源、成功身份
复用、暂时空响应、持续失败上限、刷新间隔、并发合并、旧请求隔离、注册失败
保留原身份和取消等待。CI 对这些场景执行 `go test -race`。

这些检查验证客户端恢复逻辑；反馈设备能否恢复播放仍需实际版本验证。
webOS 使用独立 JS provider，本次 Go 核心修改不改变其取源策略。
