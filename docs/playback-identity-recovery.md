# 匿名播放身份与空响应恢复

## 问题证据

2026-10-31，[公开反馈 #109](https://github.com/aston314/hongguo-tv-releases/issues/109)
在同一进程、同一视频上进行匿名身份 A → B → A → B 的对照：A 两次取得片源，
B 两次都是 HTTP 200 空响应。它支持“取源结果与身份相关”，尚不能确定上游原因、
身份有效期或认定全部空响应都由身份造成。

此阶段尚未取得媒体 URL，与 MPV/Media3 的解码错误分开处理。

## 请求与恢复规则

- 播放身份独立于登录账号，通过匿名 `POST /service/2/device_register/` 注册；
  不读取账号 Cookie、Token，也不改动登录状态。仍仅在当前核心进程内缓存。
- 取源使用参考包相同的 `api5-normal-sinfonlineb.fqnovel.com/novel/player/multi_video_model/v1/`，
  请求体使用普通 JSON 字节，并对实际发送的原始字节签名；清晰度、codec 策略及媒体缓存不变。
- `mixed_video_id_map` 按参考播放包固定使用 `1004` 分桶；目录返回的 `content_type` 和
  `video_category_type` 只用于展示/筛选，不直接作为播放请求桶。缓存仍保留调用方类型维度，
  避免不同页面状态复用错误的准备任务。
- Android/桌面 Go 核心的生产播放地址使用一个独立的匿名播放身份，按有界顺序尝试
  `api5-normal-sinfonlineb` 主线路及 `api5-normal-hl` 兼容线路；本地 fixture 或自定义 endpoint
  不会扩散到公网线路。生产环境不再同时注册六个身份并发竞速，避免连续切集时放大空响应
  和设备注册请求。
- 生产请求同一身份最多尝试 2 次。HTTP 200 空体、缺少 `video_model`、空 `video_list`，以及业务码
  `110001` 统一归类为当前 `vid` 的 `StreamMiss`；任一请求成功就直接使用结果。
- 进入恢复前，先对同一身份做最多 2 次确认，间隔约 2 秒。确认仍失败后最多注册 4 个候选
  匿名身份；每个候选必须先对同一个 `vid` 成功取到片源，才会替换活动身份。
  候选失败不会覆盖当前身份，也不会递归注册。
- 同一个 `vid` 同时只允许一个恢复任务，恢复开始后 10 分钟内不再次注册。生产身份恢复最多
  `1 + 1 + 4 = 6` 次播放接口请求；本地 fixture 的旧恢复测试仍可使用原有三次预算，
  正常首线路成功时不会额外触发身份恢复。
- HTTP 非 200、网络/读取错误、超时、其它业务错误、无效 JSON、codec 筛选后没有可用源、
  媒体下载/解密/解码失败，都不触发身份刷新。

## 播放签名与兼容回退

2026-11-02 对照 `jackotom/hongguo-drama` v5.4 的播放签名修复，确认其
`EMPTY_RESPONSE` 与本项目 `VIDEO_MODEL_EMPTY` 都包含 HTTP 200 空正文。
参考记录显示补签后有真实取源、下载和解码成功，但也有签名与无签名请求同为空的
结果，不能据此宣称消除全部上游故障。

Go 核心和 webOS 独立服务复用项目已有的完整签名算法及已验证的 F13 branch 2，
没有引入外部签名服务、参考项目代码或新依赖。播放签名的内外层应用版本保持
`7.1.3.32`，账号签名仍为原来的 `7.3.5.32`，账号固定向量必须保持不变。
最终发送的 query、实际 POST 字节、`ts`/`X-Khronos`、`_rticket`/请求票据必须一致。
每次重试或换身份重新计算签名，保持原播放 UA、分集 ID、codec 和媒体处理不变。

生产身份最多两次请求：带签名的 `api5-normal-sinfonlineb` 主机 → 带签名的官方备用主机
`api5-normal-hl.fqnovel.com`。第二次使用新连接，只在 StreamMiss 后进入此兼容路线；
本地 fixture/自定义 endpoint 仍保留原有无签名兼容请求，不增加生产身份总预算、注册频率或 UI 重试。
Go 的本地 fixture/自定义 endpoint 不会因重试而跳出到公网。webOS 纯预取仍只
发起一次请求，前台接管后继续共享同一尝试数、连续空体计数和取消路径。

新增受控检查覆盖实际请求字节与签名绑定、票据跨秒、播放/账号版本隔离、
主机白名单、原无签名兼容路径、新连接、重签及传输错误脱敏。签名成功不能证明
设备已出画面或所有网络均恢复；实网及 CI 验证结果应另行记录。

## 并发、取消与失败边界

- 前台播放、下载和预取共享注册/刷新中的任务。并发旧身份失败只发起一次刷新；
  刷新期间新来的请求等待同一个结果，迟到的旧身份失败直接复用已有替换身份，
  不能再次覆盖它。
- 两次恢复发起时间至少间隔 10 分钟，注册失败也计入间隔。它是本地防止注册风暴
  的保护间隔，不代表上游身份有效期；间隔结束后允许后续请求再次恢复。
- 刷新成功后复用新身份；刷新注册失败保留原身份，避免将可用缓存清空。
- 设置中填写的手机红果 `did` 和可选 `uid` 只作为默认播放地址失败后的最后兜底；请求时分别
  映射为 `device_id` 和 `iid`，不带账号 Cookie，也不参与历史、收藏、点赞、评论或预约接口。
- 请求取消后可立即退出等待，不再发起后续取源请求；共享注册使用自己的 8 秒
  超时，一个请求取消不能中断其他请求需要的注册。
- 诊断日志只记录刷新动作及既有的空响应状态、长度、上游 logid，不记录设备
  身份三元组、账号凭据、签名或完整媒体 URL。

## 验证

`minireel_identity_recovery_test.go` 用本地 HTTP fixture 验证坏身份换源、候选同 `vid`
验证后才发布、成功身份复用、`110001`/缺失模型/空列表 StreamMiss、持续失败上限、
恢复间隔、并发合并、旧请求隔离、注册失败保留原身份和取消等待。CI 对这些场景执行
`go test -race`。

这些检查验证客户端恢复逻辑；反馈设备能否恢复播放仍需实际版本验证。

## webOS 独立服务

webOS 的 JS Service 同样接入有上限的匿名播放身份恢复。注册域名、账号登录、
Range 按需读取和切集方式不变。初始注册与刷新共用 `playback-identity.js`，
成功身份只在当前 Service 运行期缓存。

- 每个纯预取准备任务仍只请求一次，不主动换身份；前台接管后共用原任务的尝试数和空响应计数。
- 只有同一身份连续 3 次 HTTP 200 空体（包括纯空白）才允许换一次身份，替换后
  最多再请求 3 次。前台与预取交接合计最多 6 次，不重新开启页面重试循环。
- HTTP/网络临时错误保留原有最多 3 次预算，不计入连续空体；业务拒绝、无效
  JSON、缺少模型、清晰度或媒体/解码错误均不触发换身份。
- 并发不同集共享刷新，新请求等待刷新，旧身份迟到失败不能清除新身份。
  注册失败保留旧身份，刷新开始后 30 秒内不再次注册，失败也消耗冷却。
- 每个等待者可独立取消。共享注册有 8 秒总时限，不被单个调用取消；Service
  关闭时取消注册，超时或关闭后迟到响应不能重新安装身份。
- Service 关闭时也取消尚未完成的取源任务；若 Luna 在同一进程中再次唤醒
  Service，重新建立身份缓存，旧任务和迟到注册结果不能进入新一轮播放。
- 保留各自请求的脱敏阶段、HTTP 状态、响应字节和总尝试数。前台失败不被
  后台成功覆盖，注册恢复失败也不把原始 HTTP 200 空体误写成上游 HTTP 502。

`tests/webos-playback-identity.test.cjs` 验证缓存、冷却、取消、总超时和迟到结果；
`tests/webos-prefetch-recovery.test.cjs` 通过独立 transport 和真实本机 HTTP Service
验证换身份恢复、前后台共享预算、不同剧集并发、失败保留旧身份、非适用错误
以及诊断隔离、同一 Service 关闭后重新唤醒。`scripts/verify_webos.sh`
同时检查该模块并验证打包后的依赖。
这些受控检查不等于已在反馈者的 LG 电视或网络验证。
