# MPV 音画同步输出

根据 Android 6 ZIDOO X9S HDMI 实机对照和用户确认，MPV 统一采用以下输出配置：

- `ao=audiotrack,opensles`：优先 AudioTrack，初始化不支持时仍允许 OpenSL ES。
- `audiotrack-pcm-float=no`：沿用整数 PCM 输出配置。
- `audio-samplerate=48000`：由 MPV 内部实时重采样到 48 kHz。
- `audio-delay=0.10`：音频相对视频延后 100 毫秒。

用户明确要求 MPV 所有设备使用同一配置，不按型号、系统版本或解码模式区分。
不新增设备名单、偏移设置或测试桥接入口。这些选项在创建 libmpv 实例、初始化之前
设置，复用实例换源时保持有效，销毁后重建也重新设置；没有修改切源状态机、stop fence
或 Surface 生命周期。仅 Android MPV 适配器使用该策略。

播放诊断从 MPV 的实际 `current-ao`、`audio-out-params/samplerate` 与 `audio-delay`
属性读取值，音频偏移显示带正负号的毫秒数。不能用配置值替代实际读回。

## 实机证据与边界

对照包由最新主线 `7647f25` 衍生的测试分支构建，使用原正式签名覆盖安装，保留用户数据。
固定 MPV 库、HEVC 视频轨、原始 AAC 44.1 kHz 音轨和 1 倍速，依次比较后端、重采样和偏移：

1. AudioTrack 单独替换未解决用户感知的偏差。
2. 离线 48 kHz 用户确认改善；实时 48 kHz 确认实际输出 48000 后，用户仍观察到偏差。
3. 同包比较 `0` 及正负 `25/50/100` 毫秒；实际属性均已读回。
4. 用户先确认负 100 毫秒使声音跑到嘴型前，随后确认 0 时也抢先，最终确认正 100 毫秒更合适，
   并要求将正 100 毫秒应用到 MPV 所有设备。

对应的双向测试构建提交为 `e273f45`，签名 CI 41024062998 与完整 CI 41024062973 通过。
之前实时采样率对照覆盖首次播放、seek、换源、暂停恢复、暂停状态换源及前后台恢复；
连续播放额外记录约 30 秒，无播放错误或新增掉帧。

AudioFlinger 稳态音轨仍为普通 Mixer、Flags 0x000；没有证据表明获得 FAST 通道。
这是一台实体设备的用户听感确认及全设备产品策略，尚未代表其他设备完成实机验收，
也没有仪器测出的绝对音画差值。正式代码不包含临时对照页、CI-only 开关或任意 MPV 参数入口。
